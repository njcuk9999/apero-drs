# Developer how-to guides

Practical changes to the APERO codebase, organized around the files and
contracts developers need to update together.

Use the guide matching the code you need to change. Each guide identifies the
definition, implementation, callers, tests, and documentation that should be
updated together.

| Change | Guide |
| --- | --- |
| Add a constant and instrument overrides | [Add a constant](add_a_constant) |
| Add an internal keyword and FITS card mapping | [Add a FITS keyword](add_a_keyword) |
| Add a processing step and place it in sequences | [Add a recipe](add_a_recipe) |
| Define a file type or product | [Add a file definition](add_a_file_definition) |
| Register and implement a diagnostic plot | [Add a plot](add_a_plot) |
| Create a new instrument package | [Add an instrument](add_an_instrument) |
| Update user-facing documentation | [Write APERO documentation](write_documentation) |
| Prepare a focused, searchable change | [Best practices for Git commits](git_commits) |
| Follow code organization and package boundaries | [Python style and architecture](python_style) |
| Validate a code or science change | [Run APERO tests](run_the_tests) |
