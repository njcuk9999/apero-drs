# APERO developer documentation

Architecture, contribution workflows, and internals for people changing APERO.

Start with the architecture overview to understand package boundaries. Use a
how-to guide for a concrete change; the generated APERO reference describes
the current public recipes and tools, while algorithm pages explain their
scientific behavior independently of command-line wrappers.

| Topic | Purpose |
| --- | --- |
| [Architecture overview](../developer) | Package layout, dependency direction, and the boundary between APERO wrappers and reusable core algorithms. |
| [How-to guides](how_to/) | Step-by-step changes such as adding a recipe, constant, keyword, plot, or instrument. |
| [Developer environments](../reference/developer_environments) | Conda, editable installs, profiles, and source-checkout workflow. |
| [Core algorithms](../algorithms/) | Scientific method, assumptions, equations, and quality checks. |
| [APERO recipe and tool reference](../apero/) | Generated inventory and detailed interfaces from the active APERO definitions. |
